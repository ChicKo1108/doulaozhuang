# 豆老庄服务器离线部署流程

适用场景：代码在本地开发，服务器不使用 GitHub 拉取代码；通过压缩包或 Docker 镜像传到服务器部署。

当前部署文件为 [compose.yaml](../compose.yaml)、[Dockerfile](../Dockerfile) 和 [deploy/entrypoint.sh](../deploy/entrypoint.sh)。API 容器启动时会自动执行 Prisma 的生产迁移，再启动 API 服务。

> 本文中的 `~/doulaozhuang` 是服务器项目目录，可按实际目录替换。所有命令均在项目根目录执行，除非特别说明。

## 一、部署方式选择

| 方式 | 适用情况 | 服务器需要访问的网络 |
| --- | --- | --- |
| A. 源码包部署（默认） | 服务器可正常访问 Docker Hub 与 npm Registry，只是不使用 GitHub | Docker Hub、npm Registry |
| B. 镜像包部署（推荐给网络受限服务器） | 服务器 npm 安装或 Docker 构建很慢、失败，或希望部署过程不联网 | 首次需要已有 Docker 基础镜像；日常部署无需 GitHub/npm |

两种方式都不会删除 `postgres-data`、`pattern-storage`、`caddy-data` 等 Docker 卷，因此不会因更新 API 而清空数据库、图纸素材或 HTTPS 证书。

## 二、首次部署（服务器只需做一次）

### 1. 安装并确认 Docker

```bash
docker --version
docker compose version
```

### 2. 创建部署目录和生产环境变量

```bash
mkdir -p ~/doulaozhuang/releases ~/doulaozhuang/shared
chmod 700 ~/doulaozhuang/shared
nano ~/doulaozhuang/shared/.env.production
chmod 600 ~/doulaozhuang/shared/.env.production
```

`~/doulaozhuang/shared/.env.production` 示例（只在服务器保存，绝不放入压缩包或 Git）：

```dotenv
API_DOMAIN=api.doulaozhuang.cn
POSTGRES_DB=douzi
POSTGRES_USER=doulaozhuang
POSTGRES_PASSWORD=替换为高强度数据库密码
JWT_SECRET=替换为随机长字符串
WECHAT_APP_ID=wx你的AppID
WECHAT_APP_SECRET=你的小程序AppSecret
```

生成 `JWT_SECRET`：

```bash
openssl rand -hex 32
```

> 当前 `compose.yaml` 默认使用 Docker 内 PostgreSQL，而不是阿里云 RDS。若切换到 RDS，应另行调整 Compose 的 `DATABASE_URL` 和 `postgres` 服务，不要在本流程中混用两套数据库。

### 3. 服务器安全组与域名

- 放行 TCP `80`、`443`，供 Caddy 自动申请 HTTPS 证书。
- 域名 `api.doulaozhuang.cn` 的 A/AAAA 记录指向此服务器公网 IP。
- PostgreSQL `5432` 不对公网开放；它只在 Docker 内部网络使用。

## 三、方式 A：本地源码包上传，服务器构建（默认）

### 1. 本地打包

先确认工作区包含要发布的代码，再创建不含密钥、依赖目录和无关小程序资源的发布包：

```bash
git status --short
git diff --check
release_tag=$(date +%Y%m%d-%H%M%S)
tar \
  --exclude-vcs \
  --exclude='node_modules' \
  --exclude='**/node_modules' \
  --exclude='**/dist' \
  --exclude='.env' \
  --exclude='.env.*' \
  --exclude='.pattern-storage' \
  --exclude='apps/miniprogram' \
  --exclude='assets' \
  --exclude='docs' \
  -czf "../doulaozhuang-${release_tag}.tar.gz" .
shasum -a 256 "../doulaozhuang-${release_tag}.tar.gz"
```

`apps/miniprogram` 不参与 API Docker 构建，因此从服务器发布包中排除；小程序应单独在微信开发者工具上传。

### 2. 上传发布包

在本地执行，将 `服务器IP` 替换为实际地址：

```bash
scp "../doulaozhuang-${release_tag}.tar.gz" ubuntu@服务器IP:~/doulaozhuang/releases/
```

### 3. 服务器解压并部署

在服务器执行，将 `发布标识` 替换为上一步生成的时间戳：

```bash
release_tag=20260821-153000
release_dir="$HOME/doulaozhuang/releases/$release_tag"
mkdir -p "$release_dir"
tar -xzf "$HOME/doulaozhuang/releases/doulaozhuang-${release_tag}.tar.gz" -C "$release_dir"
cd "$release_dir"

docker compose \
  --env-file "$HOME/doulaozhuang/shared/.env.production" \
  up -d --build --force-recreate api caddy
```

这一步不重新创建 PostgreSQL 容器；API 会等待已有数据库健康，再执行 `prisma migrate deploy`。

### 4. 验证

```bash
docker compose \
  --env-file "$HOME/doulaozhuang/shared/.env.production" \
  ps

docker compose \
  --env-file "$HOME/doulaozhuang/shared/.env.production" \
  logs --tail=100 api

curl --fail --silent --show-error https://api.doulaozhuang.cn/api/v1/health
```

预期健康检查响应：

```json
{"status":"ok","service":"doulaozhuang-api"}
```

## 四、方式 B：本地构建 Docker 镜像，服务器离线加载

当服务器构建镜像过慢或无法访问 npm Registry 时使用。若本地电脑是 Apple Silicon、服务器是常见的 x86 Ubuntu，则必须构建 `linux/amd64` 镜像。

### 1. 本地构建并导出镜像

```bash
release_tag=$(date +%Y%m%d-%H%M%S)
docker buildx build \
  --platform linux/amd64 \
  --tag "doulaozhuang-api:${release_tag}" \
  --load .

docker save "doulaozhuang-api:${release_tag}" \
  | gzip > "../doulaozhuang-api-${release_tag}.tar.gz"
shasum -a 256 "../doulaozhuang-api-${release_tag}.tar.gz"
```

同时按“方式 A”的“本地打包”步骤创建源码包。服务器仍需要 `compose.yaml`、`deploy/Caddyfile` 和环境变量；但不再在服务器执行 `npm ci` 或 Docker Build。

### 2. 上传源码包和镜像包

```bash
scp "../doulaozhuang-${release_tag}.tar.gz" \
    "../doulaozhuang-api-${release_tag}.tar.gz" \
    ubuntu@服务器IP:~/doulaozhuang/releases/
```

### 3. 服务器加载并启动

```bash
release_tag=20260821-153000
release_dir="$HOME/doulaozhuang/releases/$release_tag"
mkdir -p "$release_dir"
tar -xzf "$HOME/doulaozhuang/releases/doulaozhuang-${release_tag}.tar.gz" -C "$release_dir"
gzip -dc "$HOME/doulaozhuang/releases/doulaozhuang-api-${release_tag}.tar.gz" | docker load
cd "$release_dir"

docker tag "doulaozhuang-api:${release_tag}" doulaozhuang-api:latest
docker compose \
  --env-file "$HOME/doulaozhuang/shared/.env.production" \
  up -d --no-build --force-recreate api caddy
```

然后按“方式 A”的“验证”步骤检查服务。

## 五、日常更新检查清单

每次更新按以下顺序执行：

1. 本地完成代码测试并检查 `git diff --check`。
2. 打包时排除 `.env*`，不要把 `WECHAT_APP_SECRET`、数据库密码、`JWT_SECRET` 传到压缩包。
3. 上传包后创建新的 `releases/<时间戳>` 目录，不覆盖旧版本目录。
4. 只重建 `api caddy`，不执行 `docker compose down -v`，不删除 Docker 卷。
5. 看 API 日志，确认迁移完成和健康检查成功。
6. 在小程序真机或开发者工具验证登录、图纸上传、豆仓读取。

## 六、常用排查命令

### API 容器不健康

```bash
docker compose --env-file "$HOME/doulaozhuang/shared/.env.production" logs -f api
docker compose --env-file "$HOME/doulaozhuang/shared/.env.production" ps
```

### Prisma 引擎缺失

若日志出现 `Cannot find module '@prisma/engines'`，说明服务器使用的是修复前镜像。确认发布包包含最新 [Dockerfile](../Dockerfile) 与 [deploy/entrypoint.sh](../deploy/entrypoint.sh)，然后重新执行方式 A 的构建命令，或方式 B 的本地构建和镜像加载命令。

### 入口脚本不存在或无法执行

若出现 `exec /app/deploy/entrypoint.sh: no such file or directory`，检查发布包中的脚本换行符：

```bash
file deploy/entrypoint.sh
sed -n '1,10l' deploy/entrypoint.sh
```

输出中不应出现 `CRLF` 或 `\r$`。本仓库当前脚本已使用 LF；若本地编辑器改成 CRLF，请改回 LF 后重新打包。

### 数据库迁移权限错误

生产环境入口使用 `prisma migrate deploy`，不会创建 Prisma shadow database。若仍报权限错误，检查 `POSTGRES_USER` 是否拥有目标库的建表、修改表和枚举类型权限。

## 七、回滚

保留旧发布目录和旧镜像标签即可快速回滚。切换到上一个目录，使用对应镜像重新启动 `api caddy`；不回滚数据库迁移。

```bash
previous_dir="$HOME/doulaozhuang/releases/上一个发布标识"
cd "$previous_dir"
docker compose \
  --env-file "$HOME/doulaozhuang/shared/.env.production" \
  up -d --no-build --force-recreate api caddy
```

> 数据库迁移通常不可自动回滚。发布包含迁移时，应先备份数据库，并确认新版本 API 已健康后再清理旧镜像和旧发布包。
