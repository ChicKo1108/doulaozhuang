# 豆老庄｜开发计划（MVP）

## 1. 目标与边界

在首个可上线版本中交付以下闭环：用户维护 Mard 221 色母色卡库存 → 选择拥有的标准套装（24/48/72/96/120/221，默认 221）→ 上传原始图片或已有拼豆图纸图片 → 调用既有算法生成受限 Mard 图纸 → 确认入库 → 开始拼/扣减库存 → 查看缺豆并入库。

本计划不包含社区、交易、手工建图、CSV/PDF 导入和其他品牌色卡。图纸转换算法本身不在本项目重写范围内；本项目负责可靠地调用、校验和呈现其结果。

## 2. 实施原则

- 先建立 **Mard 色卡 + 库存流水** 两个不可变的业务基础，再接入图纸转换与制作流程。
- 所有库存写操作在服务端数据库事务中完成；前端不得自行计算或覆盖库存余额。
- 转换结果必须先进入“待确认”状态，用户确认后才创建图纸并参与库存统计。
- 每个阶段结束都可独立验收和演示，避免在最后集中联调。

## 3. 阶段总览

| 阶段 | 建议周期 | 目标 | 阶段产物 |
| --- | --- | --- | --- |
| 0. 项目定标 | 第 1–2 天 | 补齐外部依赖与产品基线 | 算法接口契约、Mard 色卡数据、页面原型确认 |
| 1. 小程序工程与账号 | 第 3–4 天 | 建立可运行的小程序与后端骨架 | 小程序工程、部署环境、微信登录、基础 UI |
| 2. 色卡与豆子库 | 第 2 周 | 用户可维护 Mard 221 色库存 | 色卡、库存 CRUD、盘点流水、小程序页面 |
| 3. 图片转图纸 | 第 3 周 | 用户可上传并确认自动转换图纸 | 上传、异步任务、算法适配、转换确认页 |
| 4. 制作与库存联动 | 第 4 周 | 图纸可开始、完成并准确扣减 | 预占、实际用量、库存流水、图纸详情 |
| 5. 补豆与小程序收口 | 第 5 周前半 | 缺口可汇总、购买并入库 | 补豆清单、小程序体验完善、异常状态 |
| 6. 上线验证 | 第 5 周后半 | 完成质量、性能与发布准备 | 自动化测试、监控、体验版、上线清单 |

周期按 1 名全栈开发 + 1 名产品/设计协作估算，调整后目标为 **5 周 MVP**；若算法项目接口尚未稳定，阶段 3 会成为关键路径。

## 4. 分阶段执行清单

### 阶段 0：项目定标

**任务**

1. 确认 Mard 221 色母色卡及 24/48/72/96/120/221 六种套装的权威色号清单，整理成版本化 JSON/CSV，并由产品验收。
2. 与图纸转换算法项目确定接口：输入图片 URL、来源类型、目标格数、`palette=mard-221`、`kit_id`；输出状态、网格图、色号用量、实际使用套装、算法版本和错误码。
3. 收集至少 20 张测试图片，覆盖照片、插画、透明 PNG、已有图纸截图、低清晰度和大尺寸图片。
4. 确认第一版预设格数、允许的图片格式/大小、转换超时时间，以及失败后的用户提示文案。
5. 确认小程序视觉基础：品牌色、字号、间距、底部导航和页面导航规范。

**验收**

- Mard 221 色母色卡数量为 221、色号无重复；6 个标准套装均有确定色号清单，默认项为 221，产品与算法项目使用同一版本。
- 可用一份真实图片请求算法并获得包含 Mard 色号和数量的示例响应。
- 已确定接口负责人、联调环境地址和变更通知方式。

### 阶段 1：工程与账号

**任务**

1. 初始化 Monorepo：`apps/miniprogram`（微信小程序原生 JavaScript）和 `apps/api`（NestJS），建立共享领域定义包。
2. 配置本地、测试、生产三套环境变量；提供 Docker 开发环境、数据库迁移和种子数据命令。
3. 接入 PostgreSQL、对象存储和统一错误响应；生成请求 ID 并接入结构化日志。
4. 实现微信小程序 `wx.login` 换取业务 token，并完成登录态管理。
5. 搭建小程序页面路由、主题令牌、空状态/加载态/错误态组件。

**验收**

- 微信开发者工具和真机均可启动并显示正确账号状态。
- API 健康检查、数据库迁移、对象存储测试上传在测试环境通过。
- 未登录访问业务接口返回统一的 401 错误；不同用户无法读取彼此测试数据。

### 阶段 2：Mard 色卡与豆子库

**任务**

1. 创建 `mard_colors`、`mard_color_kits`、`beads`、`inventory_transactions` 表及迁移；导入 Mard 221 色母色卡和 6 种标准套装配置。
2. 开发色卡查询、库存列表、新增库存、编辑预警值、手动盘点 API。
3. 实现库存流水：采购入库、盘亏/盘盈调整；每次调整回写余额并保存原因和关联记录。
4. 制作小程序豆子库：色块/色号搜索、低库存筛选、按 Mard 色号或库存数量排序、色卡选择器、库存卡片、数字步进器和盘点记录。
5. 为余额更新、重复提交和非法色号编写单元测试。

**验收**

- 系统仅提供 Mard 24/48/72/96/120/221 色标准套装，默认选择 221；用户只能从 Mard 221 母色卡中选择豆子，同一色号不能重复建库存。
- 任意一次库存修改均可在流水中找到原因、变化量和修改后余额。
- 小程序刷新后看到一致库存；按色号、库存升序/降序筛选结果正确。

### 阶段 3：图片上传与自动转图纸

**任务**

1. 实现图片直传：仅接受 PNG/JPG/JPEG/WebP，前后端限制类型、大小和图片像素；生成缩略图。
2. 创建 `conversion_jobs`、`patterns`、`pattern_colors` 表；实现任务创建、状态查询、幂等键和超时处理。
3. 在 `converter-client` 封装算法服务调用，支持轮询或回调，记录算法版本、原始请求和可读错误码。
4. 校验算法结果：所有颜色属于 Mard 221 母色卡且属于用户选择的套装、每色用量为正整数、总量可校验、文件归属正确。
5. 实现上传与转换页：选择“原始图片/已有图纸图片”、预设格数、进度反馈、失败重试。
6. 实现结果确认页：原图/网格图对照、尺寸、颜色数、总用豆数、Mard 用量表、改名和重新转换。
7. 用户确认后创建图纸，初始状态为“待拼”；未确认结果不进入图纸库。

**验收**

- 两类来源图片都能完成“上传 → 转换 → 确认入库”。
- 算法返回色卡外色号、重复回调、超时或失败时，不产生错误图纸或库存记录。
- 已确认图纸的每色用量之和等于总用豆数，且全部为 Mard 色号。

### 阶段 4：图纸详情、制作与库存联动

**任务**

1. 完成图纸库列表、状态/来源/颜色筛选、图纸详情和生成网格图预览。
2. 创建 `craft_sessions`、`craft_usages`、`inventory_reservations` 表；实现开始制作、保存实际用量、完成、取消接口。
3. 在“开始拼”事务中锁定库存，计算可用量并创建预占；库存不足时仍允许开始，但返回缺口。
4. 在“完成”事务中按实际用量扣减库存、写消费流水、结算预占并更新图纸状态。
5. 实现详情页用量表，实时展示计划量、可用库存、已预占和缺口；展示制作操作与确认提示。
6. 编写并发和幂等测试：两张图纸争抢同一色号、网络重试、重复完成、取消后重新开始。

**验收**

- 两张进行中图纸不会重复使用同一份可用库存。
- 完成、取消、盘点后，当前库存与流水累计结果一致。
- 已完成图纸无法静默修改实际消耗；重新转换生成新版本，不影响历史制作记录。

### 阶段 5：补豆清单与小程序收口

**任务**

1. 创建 `shopping_items`，按 Mard 色号合并各图纸缺口，保留关联图纸来源。
2. 实现“正在拼缺豆/全部计划缺豆”、色号区间分组、建议购买量编辑与已购买标记。
3. 实现“购买入库”：将已购数量写入库存和采购流水，并同步刷新缺口。
4. 完成概览页：库存种类、低库存、正在拼、缺豆摘要和继续拼入口。
5. 完成触控、图片预览、表单键盘和小程序权限/合法域名适配，并在真机验证。
6. 梳理空状态、上传失败、转换失败、无网络、登录过期与权限错误的显示和重试入口。

**验收**

- 同一 Mard 色号在补豆清单只出现一项，并能查看关联的缺口图纸。
- 入库后库存和补豆清单立即按服务端结果刷新。
- 微信小程序的核心闭环可完成，关键文案和数量口径一致。

### 阶段 6：测试、发布与运营准备

**任务**

1. 完成 API 单元测试、转换算法集成测试、库存事务测试，以及小程序端到端测试。
2. 使用阶段 0 测试集跑转换回归，记录成功率、平均耗时、色卡外输出率和失败原因分布。
3. 增加监控告警：转换超时/失败率、库存事务异常、上传失败、登录失败和 API 错误率。
4. 完成隐私政策、微信小程序隐私配置、对象存储跨域/访问控制、数据库备份与恢复演练。
5. 发布测试环境，邀请小范围种子用户试用；修复 P0/P1 问题后灰度发布。

**验收**

- 核心闭环端到端自动化测试通过；库存相关单元测试和并发测试全绿。
- 转换任务失败可定位到用户、任务、算法版本和错误码，且可安全重试。
- 小程序审核材料、生产域名、备份恢复和监控告警均已验证。

## 5. 关键依赖与风险

| 风险/依赖 | 影响 | 应对方式 |
| --- | --- | --- |
| Mard 221 色卡数据不完整或与算法不一致 | 库存与图纸无法准确匹配 | 在阶段 0 固化色卡版本；算法输出只传 Mard 色号 |
| 既有算法接口不稳定 | 阶段 3 及之后受阻 | 用适配层隔离；定义超时、回调、幂等和版本契约；准备模拟服务联调 |
| 图片质量与尺寸差异大 | 转换失败或结果不佳 | 限制输入，提供预设格数、失败重试和测试集回归 |
| 库存并发扣减 | 出现重复预占或负库存 | 数据库事务行锁、不可变流水、幂等键、并发测试 |
| 小程序文件/网络限制 | 上传或预览流程受限 | 早期在真机和开发者工具验证上传、预览、合法域名与登录 |

## 7. 当前第一步

先执行“阶段 0”。开始编码前，需要在项目中落定以下三项输入：

1. Mard 221 色卡的标准文件及其版本号。
2. 现有图纸转换算法项目的仓库位置或可调用测试接口，以及一份成功响应样例。
3. 第一版支持的预设格数、最大上传文件大小和图片转换超时阈值。
